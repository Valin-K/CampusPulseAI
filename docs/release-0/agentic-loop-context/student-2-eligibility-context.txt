The eligibility-gated Student enrolment change is already implemented. Review
whether it meets the approved Student 2 rule and identify only genuine remaining
risks.

Current Student 2 architecture:
- The Blazor frontend calls the Student 2 backend.
- The Student 2 backend calls the Course Management database API.
- The database API owns prerequisite rules and SQLite data.
- The Student 2 backend calls Student 1 Academic Records to create official enrolments.

Approved business rules:
- The Course must exist and be active.
- All configured Course prerequisites must meet their minimum grades.
- There is no Student-status or financial-hold rule in the approved scope.
- Do not invent authentication, waiver, finance, or other requirements.

Implemented behaviour:
- Home.razor no longer provides direct enrolment from the Course catalogue.
- PrerequisiteEligibility.razor checks prerequisites and reveals Enrol only
  after a successful result.
- CreateCourseEnrollmentRequest sends the Course code and completed Course
  evidence.
- StudentCourseAccessController recalculates eligibility through
  ICourseCatalogueClient before it calls Academic Records.
- Ineligible requests return HTTP 409 titled "Prerequisites not met".
- A mismatched Course eligibility response is rejected.
- Courses with no prerequisites are checked using an empty evidence list.
- Tests verify that Academic Records is not called for an ineligible request.
